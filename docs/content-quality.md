# AI 热点质量评估标准

> 统一人工审核、规则评分和未来 AI 辅助判断的判定口径。本文件定义"怎样判断"，不代表当前所有能力均已自动实现。

## 1. 基本原则

1. **事实、推断、观点分离**：平台字段和明确披露属于事实；规则识别属于推断；博主解读属于观点。展示和存储时不得混为一体。
2. **证据优先**：转载、商单、职业背景、官方核验和异常判定都必须附证据；证据不足时使用 `unknown`、`candidate` 或 `needs_review`。
3. **不以单一指标排名**：高频、高互动或高粉丝量不直接等于高质量；总分必须能展开为分项。
4. **不误伤低频优质来源**：更新频率用于描述内容节奏，不直接扣减长期专业质量。
5. **不贬低正常质疑**：建设性质疑、事实纠错、技术争论和不同立场均可形成有价值观点。
6. **缺失不等于零**：无法获取的互动、评论、动态或职业信息记为 `null/unknown`，并降低对应判断置信度。
7. **B站动态是一等内容**：有信息价值的文字、转发、视频投稿和专栏动态进入热点发现、主题聚合、观点对比和内容评分。
8. **渐进自动化**：首版使用规则、证据和置信度；未来 AI 只能输出候选判断，不得无证据直接定性商单、抄袭、事实错误或职业身份。

## 2. 来源与博主标签

每个来源可同时拥有多个内容标签：

| 标签 | 定义 | 典型价值 |
|---|---|---|
| 横向测评 | 对多个模型、产品或工具进行相同任务下的比较 | 使用边界、差异、成本和稳定性 |
| 即时资讯 | 快速传播模型、产品、研究、政策和行业变化 | 时效性和事件发现 |
| 深度解读 | 解释论文、模型机制、产业背景或长期趋势 | 专业理解和背景证据 |
| 教程实践 | 提供可执行步骤、代码、工作流或复现条件 | 可操作性和复现价值 |
| 行业观点 | 对行业方向、政策、商业或社会影响提出观点 | 多元立场与趋势判断 |
| 轻度用户体验 | 普通或低频用户的真实上手、成本、失败、限制和适用人群 | 避免信息只偏向重度用户和开发者 |
| 官方来源 | 公司、实验室、产品或开源项目的正式账号 | 一手公告和事实锚点 |

`cadence_class` 仅描述发布节奏：`low_frequency`、`high_frequency`、`unknown`。它不是质量结论。

## 3. 内容类型

统一内容类型至少包括：`youtube_video`、`x_post`、`bilibili_video`、`bilibili_dynamic_video`、`bilibili_dynamic_repost`、`bilibili_dynamic_text`、`bilibili_article`、`unknown`。

B站动态处理原则：

- 原创文字观点可独立进入主题和观点对比；
- 转发若附带有价值评论，保留转发内容和评论；
- 纯转发仍可作为事件传播和近期关注信号，但内容质量贡献较低；
- 视频投稿动态与视频通过原生 ID 去重；
- 动态路由不可用时标记 `degraded`，不得推断博主"不活跃"。

## 4. 事实、推断与观点字段

| 类别 | 示例 | 处理方式 |
|---|---|---|
| 平台事实 | 原生 ID、发布时间、作者、链接、互动量 | 原样保存，记录抓取时间 |
| 明确披露 | "本视频由……赞助"、平台广告标识 | 保存原文片段和链接，可触发规则 |
| 来源事实 | 官方主页、论文 DOI、代码仓库、产品文档 | 保存可核验 URL |
| 规则推断 | 候选转载、轻度体验信号、主题候选 | 保存规则名、证据、置信度 |
| 博主观点 | "该模型更适合编程" | 作为观点保存，不自动变为事实 |
| 未知信息 | 职业身份不明、互动数据缺失 | `unknown/null`，不猜测 |

## 5. 转载溯源与同主题聚合

### 转载关系

`origin_status`：`confirmed`（有平台转载标识/原文链接/人工核验）| `candidate`（高度相似但证据不足）| `unknown`。

`relation`：`original`、`repost`、`commentary`、`translation`、`citation`、`duplicate_observation`。

同一原生内容的重复抓取可合并；转载和评论内容保留为独立记录，通过 provenance 关联。

### 同主题多观点

多个博主讨论同一事件时归入同一 `event/topic_key`，但保留各自内容和观点。允许并列展示：官方事实、技术解释、实际测试、轻度用户体验、支持/质疑/争议、结论/数据差异。首版只使用确定性关键词和明确链接形成候选主题，不自动生成"唯一正确结论"。

## 6. 可解释评分

所有分项归一化为 0–100：

```
基础分 = 0.30 × 长期专业质量 + 0.25 × 近期时效性 + 0.10 × 轻度用户体验价值
       + 0.20 × 来源可靠性 + 0.15 × 互动质量

最终分 = clamp(基础分 - 商业推广扣分 - 异常调整, 0, 100)
```

权重为首版保守默认，实际值集中在 `data/news/config/news-config.json`。

### 各维度说明

- **长期专业质量**：可核验的机构/研究/开发/产品背景、可复现实验与案例、历史纠错和引用质量。不得凭账号名称推断职业身份；不因低频更新直接扣分。
- **近期时效性**：按内容类型配置的指数衰减 `100 × exp(-ln(2) × 年龄天数 / 半衰期)`。初始半衰期：即时资讯 2 天、行业观点 14 天、横向测评 21 天、教程/深度解读 45 天。
- **轻度用户体验价值**：只有出现具体使用任务/环境、上手成本、免费额度、失败案例、适用人群等明确证据时才增加该维度。
- **来源可靠性**：考虑官方公告、论文、代码仓库、产品文档、一手演示、明确引用和历史可核验性。官方自述性能和营销结论仍应与独立测试区分。
- **互动质量**：互动量不是质量本身。数据足够时优先与作者自身历史基线比较；正常质疑和纠错不作负面信号。

## 7. 商单、软广与利益关系

只在有证据时标记：

| 证据 | 标签 | 默认处理 |
|---|---|---|
| 明确赞助声明 | `declared_sponsorship` | 记录证据，按配置有限降权 |
| 平台广告标识 | `platform_ad_label` | 记录证据，按配置有限降权 |
| 明确 affiliate 链接 | `affiliate_link` | 记录证据，按配置有限降权 |
| 作者明确披露利益关系 | `declared_interest` | 记录关系和适用范围 |
| 只有产品推荐、无利益证据 | `none_confirmed` | 不扣分 |
| 官方账号介绍自家产品 | `official_source` | 不自动当作商单，区分事实和宣传主张 |

商业推广判定必须保存 `label`、`evidence[]`、`confidence` 和 `penalty`。

## 8. 异常处理

异常检测用于提示复核，不用于自动删除。

- 样本数低于配置阈值时：`insufficient_sample`，调整值为 0；
- 样本足够时使用中位数 + MAD 或 IQR；
- 记录样本数、当前值、基线、阈值、方法和触发字段；
- 首版异常只标记 `review` 或将互动维度恢复为中性；
- 只有人工确认后才允许有限扣分。

## 9. 时间批次与近期活跃度

默认时间层统一使用 UTC 固定天数和半开区间：`[0,1)`、`[1,7)`、`[7,30)`、`[30,90)`、`[90,270)`。调度采用时间层优先：当前层全部适用来源到达终态后才进入下一层。B站当前采用人工精选，不做自动历史回溯。

近期 AI 活跃度综合：最近 AI 内容发布时间、近期 AI 内容数量和类型、B站视频/动态/专栏、已关联的其他平台近期活动。近期沉默只降低"当前时效/AI 活跃度"，不降低历史内容质量。

## 10. 置信度和降级状态

置信度表示证据完整性（0–1），不等于质量分。

来源采集状态：`success`（完整）、`partial`（部分字段缺失）、`failed`（可重试）、`degraded`（达到重试上限或能力受限）。`degraded` 只描述数据覆盖，不代表来源或博主质量下降。

## 11. 未来 AI 辅助判断约束

1. AI 输出只能是候选主题、候选转载关系、候选观点、候选体验信号或候选商业披露；
2. 输出必须包含证据片段、原文 URL、置信度和无法判断项；
3. AI 不得凭空判断职业身份、商单、抄袭、事实错误或作者动机；
4. 正常质疑和不同观点不得自动判为低质量；
5. 低置信度结果不得影响正式评分；
6. 模型、提示词、版本、输入摘要和输出需可追踪；
7. 正式启用前须使用人工标注样本评估准确率、误报和漏报，并确认调用成本。

## 12. 人工复核优先级

优先进入人工复核：

- 商单或利益关系候选；
- 原始来源争议；
- 官方数据与博主数据冲突；
- 异常互动或标题党候选；
- 同主题结论明显冲突；
- 低置信度但高影响的内容；
- B站动态/视频重复或类型无法判断。

所有人工调整应保留修改时间、理由和证据，不静默覆盖自动结果。
