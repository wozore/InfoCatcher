## 阶段架构

### MVP：静态站 + 构建时采集

```text
人工主数据 / 厂商来源 / 平台内容
          ↓
GitHub Actions 构建与采集（Secrets 注入）
          ↓
静态 JSON + RSS + Web 资源
          ↓
GitHub Pages（浏览器不直连平台 API）
```

热点扩展不提前引入运行时 Serverless：YouTube/X 构建时采集，B站人工精选进入统一管线。核心设计边界：

- 浏览器只读取静态投影，API Key 仅来自 Secrets；
- 使用 UTC 半开时间层和每来源持久游标；
- `news-registry.json` 以 `platform:native_id` 持久去重；
- 按平台独立记录额度，超默认边界前创建授权任务；
- 状态采用临时文件 + rename 原子写，并用构建锁避免并发修改；
- B站内容可参与主题和观点对比，但不使用内部 API、Cookie 自动化、逆向 SDK 或风控绕过；
- 评分保留规则、证据和置信度，AI 只可提供候选判断；
- 采集失败不得以空结果覆盖有效数据。

当前实现已偏离草案中的“每日触发、Lunr.js、B站自动采集”等内容，现行频率和模块见当前文档。

### 演进目标：SPA + Serverless

静态站验证后，按需求增量加入 API 代理、缓存、Cron、推荐逻辑、账户和推送，而不是一次性重写：

```text
SPA → Serverless Functions（代理 / Cron / 推荐）
                      ↓
                 KV / 数据缓存
                      ↓
             经批准的外部数据源
```

| 能力 | MVP | 演进目标 |
|---|---|---|
| 工具信息 | 静态 JSON | 缓存 + 定时更新 |
| 对比/筛选 | 浏览器端 | 仍以客户端为主 |
| 推荐 | 编辑推荐；行为推荐未实现 | Serverless + 本地/账户偏好 |
| 热点 | 构建时采集 + B站人工精选 | 经合规评估后扩展 |
| 维护 | GitHub Issues + 人工审核 | 可增加 AI 预审 |

## 历史里程碑与关口

原计划依次完成技术验证、内容骨架、MVP 内测、发布、反馈收集和迁移决策；日期只是 2026-07-18 的历史计划快照，不是当前承诺。架构迁移须由用户反馈、维护成本和现有静态方案限制共同触发。

## 风险与未完成设计

- 静态架构的功能上限是预期风险，方案 1 → 3 是预设演进路径。
- Cloudflare/RSSHub 绕过工具仅是早期 PoC 候选，未获准进入 MVP。
- 归档时仍未形成正式的数据流图、模块接口、完整 schema 和推荐算法详细设计；这些应在环 C 按实际需求产出。
