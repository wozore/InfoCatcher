## 1. 功能概述

InfoCatcher 作为开源项目，应允许社区贡献者/用户通过"插件"机制扩展工具数据覆盖范围、自定义对比维度、甚至添加新的视图模块，满足不同用户的个性化需求，降低社区贡献门槛。

---

## 2. 两种插件等级（按架构分）

### 2.1 方案1（静态站，当前）— 文件级插件

| 插件类型 | 说明 | 示例 |
|---------|------|------|
| **数据插件** | 贡献者通过 PR 添加 `plugins/<plugin-name>/data.json`，构建时合并到主数据源 | 某用户提交一个"教育类 AI 工具"数据包 |
| **视图插件** | 贡献者添加自定义 HTML/CSS 片段，通过约定接口挂载到站点特定区域 | 一个"工具评分雷达图"视图扩展 |
| **i18n 插件** | 社区提交翻译文件，实现多语言界面 | 英文/日文翻译包 |

**限制**：插件不能运行时安装，须合入代码仓库后通过 CI/CD 部署生效；插件间不能互相依赖。

### 2.2 方案3（SPA + Serverless，v1.0 后）— 运行时插件

| 插件类型 | 说明 | 示例 |
|---------|------|------|
| **远程数据源** | 插件注册 API 端点，系统定时拉取第三方工具信息 | 接入某评测网站的公开 API |
| **自定义视图** | 插件以 Web Component / iframe 形式动态加载到页面 | 一个"价格趋势图"插件展示历史价格变化 |
| **推荐算法插件** | 社区提交推荐模型配置，Serverless 函数加载执行 | 协同过滤 / 基于规则的推荐引擎 |

## 3. 用例分析

### Actor（参与者）

| 角色 | 说明 |
|------|------|
| **贡献者** | 为 InfoCatcher 开发/提交插件的开发者 |
| **普通用户** | 浏览和安装插件 |
| **维护者（或 CI）** | 审核插件、合并入库、触发部署 |

### Use Case

| 编号 | 用例 | 角色 | 说明 |
|:---:|------|------|------|
| UC-PLUG-01 | 提交数据插件 | 贡献者 | 按规范编写插件描述 + 数据文件，提交 PR |
| UC-PLUG-02 | 提交视图插件 | 贡献者 | 提供自定义 HTML/CSS/JS 片段及挂载点声明 |
| UC-PLUG-03 | 审核合并插件 | 维护者 | 审查插件安全性与数据准确性，合并入库 |
| UC-PLUG-04 | 浏览已安装插件 | 用户 | 在站点上查看当前已集成的插件列表 |
| UC-PLUG-05 | 卸载/禁用插件 | 用户 | 在本地关闭不需要的插件视图（localStorage） |
| UC-PLUG-06 |（未来）运行时安装插件 | 用户 | 方案3 后：一键安装社区插件仓库中的插件 |

## 4. 方案1 下的实现思路（草案）

```
src/
├── plugins/
│   ├── index.json              # 已注册插件清单
│   ├── edu-tools/              # 示例：某贡献者提交的"教育工具"数据插件
│   │   ├── manifest.json       # 插件元数据：名称、作者、版本、挂载点
│   │   └── data.json           # 工具数据
│   └── radar-chart/            # 示例：某贡献者提交的"雷达图"视图插件
│       ├── manifest.json
│       ├── template.html
│       └── style.css
└── (构建时由脚本合并 plugins/* 到主数据源)
```

**构建流程**：
```
PR 提交 → 维护者审核 → 合入 main → GitHub Actions 构建 →
  遍历 plugins/ 读取 manifest.json → 合并 data → 更新 index.json →
  部署到 GitHub Pages
```

## 5. 验收条件

- [ ] `plugins/index.json` 格式定稿，运行时能读取并展示插件列表
- [ ] 至少一个插件作为内置范例提交（如社区翻译包）
- [ ] 插件加载不影响站点首屏性能（异步加载，首屏不阻塞）
- [ ] 方案3 阶段可无缝升级为运行时插件
