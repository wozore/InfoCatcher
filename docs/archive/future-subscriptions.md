# AI 信息订阅推送系统（历史草案）

> **创建日期**：2026-07-20
> **状态**：RSS 已在环 B 实现；登录、多平台推送和推送 API 留至环 C C06。

## 目标与渠道

订阅模块让用户主动接收工具上新、价格/额度变化、排行更新和新评测，而不是等待回访。

| 渠道 | 方式 | 阶段 |
|---|---|:---:|
| RSS/Atom | 构建时生成 `feed.xml` | B（已实现） |
| 浏览器通知 | Web Push + Service Worker，需 HTTPS | B（可选，未实现） |
| 邮件、微信/飞书、B站、X | Serverless 调用平台 API，通常需 OAuth | C |

方案 1 只能随站点更新生成统一订阅内容；用户自定义时间、固定间隔和 API 触发均需方案 3。

## 身份边界

功能越强，对身份和后端依赖越高：

```text
RSS → 浏览器通知 → 邮件订阅 → 社交平台推送
无需登录   仅需 HTTPS     需要身份      需要 OAuth + 后端
```

无登录时无法跨设备保存偏好、绑定社交账号或按用户限流。可行折衷为 RSS、GitHub Watch，以及仅在当前浏览器授权的通知。

## 分阶段实现

**环 B（零登录、零后端）**：维护动态数据，构建 RSS，并提供可发现的订阅入口。

**环 C（完整订阅）**：在 Serverless 基础上依次实现 OAuth、偏好存储、定时调度、多平台发送和带认证的推送 API。用户系统应与插件系统共享认证和存储基础。
