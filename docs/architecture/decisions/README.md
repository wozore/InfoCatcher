### ADR-001：单仓库四层结构

**决策**：项目采用单一 Git 仓库，内部分为四层——源码、架构事实、开发过程、AI 入口。

**理由**：AI 助手需要固定的阅读顺序和明确的职责边界。四层结构确保每个事实只有一个权威位置。

**替代方案**：多仓库（工程仓库 + 部署仓库）——增加同步负担，AI 难以跨仓库获取上下文。

### ADR-002：纯静态站点 + GitHub Pages

**决策**：MVP 采用纯静态 HTML/CSS/JS，部署到 GitHub Pages，不引入运行时后端。

**理由**：零服务器成本、匹配开发者技能、Git 深度整合、可通过 GitHub Actions 实现构建时动态化。

---

### ADR-003：零 npm 依赖

**决策**：所有 Node.js 脚本只使用内置模块（fs、path、crypto、zlib 等），不引入 npm 依赖。

**理由**：减少安全攻击面、消除依赖漂移、降低 AI 理解项目的门槛。

---

### ADR-004：JSON 文件存储

**决策**：所有数据以静态 JSON 文件存储，Git 版本控制。

**理由**：直接可读、易于 AI 校验、无需数据库运维、变更历史可审计。

---

### ADR-005：源码与数据分离

**决策**：`src/` 放实现代码，`data/` 放运行数据，`public/` 放部署资源，三者不在同一目录。

**理由**：避免"找出所有 JS 文件"时需要排除 JSON；前端发布时只需组装而不需过滤。

---

### ADR-006：构建时采集

**决策**：热点和工具情报通过 GitHub Actions 在构建时采集，输出静态 JSON，而非浏览器运行时直接调用 API。

**理由**：保护 API 密钥、控制调用频率和成本、确保离线可用、使前端保持纯静态。
