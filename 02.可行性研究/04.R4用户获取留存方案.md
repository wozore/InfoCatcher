## 原始风险回顾

来自 [[可行性研究报告.md#R4：目标用户不使用或不持续使用|可行性研究报告 §16.2 R4]]：

| 字段 | 内容 |
|------|------|
| **风险描述** | MVP 上线后目标用户（学生群体）访问量低，或首次访问后不回访，无法收集足够反馈 |
| **根本原因** | 学生群体信息获取习惯以社交媒体为主（82.1%），主动访问静态网站的习惯未建立；竞品提供更强的社交粘性 |
| **概率** | 4（较高） |
| **影响** | 3（影响项目局部目标——反馈不足影响迭代方向判断） |
| **等级** | **12（中）** |
| **触发信号** | MVP 上线 1 周内独立访客 < 30；GitHub Star < 10；无自发用户反馈 |

原始缓解措施（报告中已有）：
- 在原有问卷渠道（微信/QQ群）主动推广 MVP
- 内容中嵌入社交分享按钮
- 利用 GitHub README 做 SEO
- 场景化页面设计为"可分享的独立入口"
- 在目标用户社群做定向推广（V2EX、即刻等）
- 直接联系问卷中留了联系方式的受访者

## 新补充方案

### 一、SEO 工具站策略（零成本持续获客）

你的站本质是 **"工具站"而非"内容站"**——用户来是为了"对比AI工具"，不是读文章。工具站的 SEO 策略与内容站完全不同：

| 维度 | 内容站 | 你的站（工具站） |
|------|--------|----------------|
| 核心流量来源 | 文章页面 | 场景对比页面 / 工具详情页 |
| SEO重点 | 内容质量+更新频率 | 页面标题/描述 + 功能完整度 + 用户停留时长 |
| 内链策略 | 文章互链 | 博客文章→工具页，单向引流 |
| 外链策略 | 铺量买链接 | 靠产品好用自然获取推荐链接 |
| 核心KPI | 流量和广告点击 | **用户留存和转化率** |

**分三期操作：**

- **P0（上线前）**：给场景对比页加上 `SoftwareApplication Schema`（评分、价格），给 FAQ 加 `FAQPage Schema`；配好 OpenGraph 标签（og:title、og:description、og:image），确保分享到社交平台显示精美卡片
- **P1（上线第一周）**：配好 Google Search Console + Google Analytics，提交 Sitemap，做好内链布局
- **P2（长期）**：持续产出"AI工具对比""如何选AI写论文"等长尾关键词内容

> 关键是：工具站的第一 KPI 不是流量，是用户留存。用户留住了，SEO 自然会好。

### 二、300+ 推广渠道清单（来自 1000UserGuide）

GitHub 上的 [[https://github.com/naxiaoduo/1000UserGuide|1000UserGuide]] 项目整理了 300+ 国内外推广渠道。对 InfoCatcher 来说，你的站本身就是"AI 工具信息站"，与大量 AI 导航目录天然对口——不是硬推广，而是互相收录。

**国内优先渠道（上线当天执行）：**

| 渠道类型 | 具体渠道 | 说明 |
|---------|---------|------|
| 产品发布平台 | V2EX「分享创造」、少数派「Tron计划」、新趣集 | 开发者和早期用户聚集地 |
| 社区论坛 | 即刻「AI探索站」「独立开发的日常」、知乎 AI Works、HelloGitHub | 可发帖分享产品故事 |
| AI 导航站 | 2AGI、AIHub、ai-bot.cn、Tap4 AI、未来百科 | 反向提交 InfoCatcher 收录 |
| 周刊/媒体 | 阮一峰科技爱好者周刊、独立开发变现周刊 | 自荐收录 |
| 开发者社区 | 开源中国、掘金、CSDN | 发技术文章顺带推广 |

**海外渠道：**

| 渠道类型 | 具体渠道 | 说明 |
|---------|---------|------|
| 产品发布 | Product Hunt、Hacker News「Show HN」、DevHunt | 科技爱好者发现新产品的地方 |
| AI 导航站 | Futurepedia、aitoolslist.io、AI Valley、AI Scout | 大量 AI 工具目录可提交 |
| 目录站 | AlternativeTo、OpenAlternative、SourceForge | 软件替代方案目录 |
| 社区 | indiehackers、dev.to、Reddit（r/opensource、r/selfhosted、r/ChatGPT）| 开发者社区 |

> **操作建议**：上线当天集中提交 15-20 个高优先级渠道，之后每周持续分批提交剩余的。

### 三、由外到内的推广飞轮

```
SEO 长尾流量 ──→ 用户通过搜索找到场景页
     ↑                    ↓
     │              对比后有收获
     │                    ↓
  更多外链 ←── 分享到社交媒体/博客
                    ↓
              → 首次访问完成"激活" ←
              → 通过 NewsLetter/RSS 回访 ←
              → 提交反馈/参与社区 ←
```

**关键环节：**

1. **激活（Activation）**——用户首次访问必须在 3 秒内理解价值，完成一次"有用的动作"（比如选一个场景→看到对比→做出决策），这是留存的前提
2. **回访机制**——AI 行业变化快，每月发一封"AI 工具月报"Newsletter/博客更新，让回访成为习惯
3. **社交传播**——每个场景页设计为"可独立分享"，自带 OpenGraph 卡片，分享到微信群/B站/知乎就像在发一个独立内容
4. **社区建设**——GitHub Discussions + 微信群双通道，用户反馈有回应、有闭环

### 四、GitHub 生态内的增长战术

| 战术 | 说明 | 预估效果 |
|------|------|---------|
| **README SEO** | 项目描述覆盖关键词（AI工具、对比、评测、开源），标签选好 | 基础曝光 |
| **HelloGitHub 提交** | 向 HelloGitHub 周刊提交项目，面向开发者群体 | ⭐⭐⭐ |
| **GitHub Trending** | Star 增长快时可能自然上榜，需要集中发力 | ⭐⭐⭐ |
| **Good First Issue** | 标一些入门级 issue，吸引贡献者（同 github-growth-hack 做法） | ⭐⭐ |
| **开源中国推荐** | 向 OSC 提交项目推荐 | ⭐⭐ |
| **相关项目 README 互链** | 在 awesome-ai-tools 等项目的 README 中争取被收录 | ⭐⭐⭐ |
