## 1. 背景：为什么 B站 只能走 RSSHub

### 已死的路

B站对第三方数据获取的打击力度是三个平台中最严的：

| 时间 | 事件 | 结果 |
|:----|:------|:------|
| 2025.07 | 第三方客户端 PiliPala 收到律师函 | 停止更新 |
| **2026.01.28** | **bilibili-API-collect**（20k+ stars）收到律师函 | **永久删库** |
| **2026.07.06** | **bilibili-api** Python SDK 收到律师函 | **永久关停** |

律师函指控核心："通过技术手段对非公开 API 接口进行系统性收集、整理，以文档和代码形式向不特定公众传播"，涉嫌违反《反不正当竞争法》《网络安全法》。

B站也无法像 YouTube 那样通过官方 API 获取公开数据——B站开放平台（open.bilibili.com）面向的是内容创作者/机构，提供稿件分发能力，**不提供视频元数据检索的开发者 API**。

### 唯一合规的免费路径：RSSHub

[RSSHub](https://github.com/DIYgod/RSSHub) 是全球最大的开源 RSS 网络，口号是"万物皆可 RSS"。它的工作原理是抓取**公开网页**（非内部 API），将网页内容转换为标准 RSS/Atom feed。

**和逆向 API 的本质区别**：
- 逆向 API：破解内部接口的签名/认证/参数，调用非公开端点
- RSSHub：抓取浏览器也能看到的公开 HTML 页面，转成结构化 feed

截至 2026 年 7 月，B站未对 RSSHub 采取法律行动。

## 2. 可获取的 B站 数据

### 2.1 UP主视频列表（核心路由）

```
https://rsshub.app/bilibili/user/video/{UP主UID}
```

**每条视频可获取的数据：**

| 字段 | 说明 | AI 热点价值 |
|:----|:------|:----|
| 视频标题 | 完整标题文本 | ⭐ 核心——热点识别 |
| 视频链接 | `https://www.bilibili.com/video/{BV号}` | ⭐ 跳转源 |
| 发布时间 | `pubDate`（RFC 822 格式） | ⭐ 时效判断 |
| 视频描述 | 简介/description | ⭐ 摘要提取 |
| 封面图 | 缩略图 URL | 展示用 |
| UP主名称 | 作者名 | 信源标记 |
| 视频时长 | 时长字符串 | 筛选长内容 |

### 2.2 UP主动态

```
https://rsshub.app/bilibili/user/dynamic/{UP主UID}
```

获取 UP主发布的所有动态（视频投稿 + 转发 + 文字动态 + 专栏），适合追踪 AI UP主的内容动向。

### 2.3 UP主专栏/图文

```
https://rsshub.app/bilibili/user/article/{UP主UID}
```

获取 UP主的专栏文章（B站的长图文功能）。部分 AI UP主会在专栏发布技术分析文章。

### 2.4 频道/合集

```
https://rsshub.app/bilibili/user/channel/{UP主UID}/{频道ID}
```

UP主创建的系列合集（如"AI 工具测评"系列），一次性获取该系列所有视频。

### 2.5 排行榜与热门

| 路由 | 用途 |
|:----|:------|
| `/bilibili/ranking/{分区ID}?` | 各分区排行榜（科技区 tid=188） |
| `/bilibili/popular` | 综合热门 |
| `/bilibili/weekly` | 每周必看 |
| `/bilibili/partion/{分区ID}` | 分区最新视频 |

### 2.6 搜索

```
https://rsshub.app/bilibili/search/{关键词}/{排序?}
```

按关键词搜索视频，排序可选：`default`（综合）、`pubdate`（最新发布）、`click`（最多播放）、`stow`（最多收藏）。

### 2.7 RSSHub 无法获取的数据

| 数据类型 | 原因 | 替代方案 |
|:----|:------|:------|
| **字幕/CC 文本** | RSS 不包含字幕 | BibiGPT（免费手动）、TikHub API（付费自动化） |
| **精确播放量/点赞/投币** | 这些数据在 HTML 页面上，RSSHub 未抓取 | B站内部 API（🔴 踩红线）、TikHub API（付费） |
| **弹幕内容** | RSSHub 有路由但数据量大、价值有限 | TikHub API |
| **评论内容** | RSSHub 无评论路由 | TikHub API |

> RSSHub 的 B站路由覆盖了"发现有价值视频"的需求（标题+描述+时间足够判断热点），但深度分析（字幕摘要、热度评估）需要额外方案。详见第 5 节。

## 3. 数据获取流程（基于 RSSHub）

```
1. 维护 AI UP主 UID 列表 → 缓存
2. RSSHub 轮询（建议间隔 30-60 分钟）
   → https://rsshub.app/bilibili/user/video/{UID}
   → 获取最新视频 feed（RSS XML 格式）
3. 解析 RSS → 提取标题/描述/发布时间/链接
4. 关键词过滤 → 筛选 AI 热点相关内容
5. 辅助：定期搜索补充新发现
   → https://rsshub.app/bilibili/search/AI工具/click
```

## 4. 技术约束

| 约束项 | 说明 |
|:----|:------|
| 公共实例限制 | rsshub.app 缓存 20 分钟，高频使用建议自部署 |
| 反爬风控 | B站网页端也有一定反爬，RSSHub 社区持续适配 |
| 数据浅 | 标题+描述+时间，无播放量和字幕（详见第 5 节补充方案） |
| 稳定性 | 依赖 RSSHub 社区维护，B站改版时可能短暂不可用 |
| 自部署成本 | 需服务器或 NAS（Docker 一键部署，资源消耗低） |

## 5. 深度数据补充方案

### 5.1 字幕获取

| 方案 | 方式 | 成本 | 自动化 |
|:----|:------|:---:|:---:|
| **BibiGPT** | 粘贴B站链接 → 下载字幕（SRT/VTT/TXT） | 免费层可用 | ❌ 手动 |
| DownSub | 同上，纯字幕下载 | 免费 | ❌ 手动 |
| **TikHub API** | `/api/v1/bilibili/app/fetch_one_video` | 付费 | ✅ API |

BibiGPT 有个额外优势：视频没有字幕时，会用 AI 语音转文字自动生成字幕。

> MVP 阶段可手动用 BibiGPT 拉取关键视频字幕。需要自动化时再接入 TikHub。

### 5.2 播放量/热度数据

B站内部 API（`api.bilibili.com/x/space/arc/search`）确实返回播放量、弹幕数、评论数等数据，但这就是 2026 年两封律师函针对的东西——**直接调用 B站内部 API = 踩红线，不能走**。

| 方案 | 风险 | 成本 |
|:----|:---:|:---:|
| B站内部 API | 🔴 律师函风险 | 免费 |
| **TikHub API** | 🟡 第三方扛合规风险 | 付费 |

### 5.3 TikHub：收费但合规的深度 API

[TikHub](https://tikhub.io) 是国内第三方社交数据平台，提供 B站 web/app 双系列 API。和 TwitterAPI.io 一样的逻辑——他们扛反爬和合规风险，你付钱拿数据。

**TikHub B站 接口覆盖：**

| 接口 | 返回数据 |
|:----|:------|
| `fetch_one_video` | 视频元数据 + **播放量/弹幕数/评论数/投币/收藏/分享** |
| `fetch_video_comments` | 评论内容（含子回复） |
| `fetch_user_info` | UP主粉丝数/播放量/获赞数 |
| `fetch_user_videos` | UP主视频列表（含每条视频统计） |
| `fetch_general_search` | 搜索结果（含视频+用户） |

**定价**：TikHub 采用按量付费/订阅制，具体价格未在文档页公开，需联系或注册后查看。

### 5.4 推荐的分层策略

```
Layer 1（免费 · 自动化）
  └─ RSSHub → 标题+描述+时间 → 热点发现

Layer 2（免费 · 手动）
  └─ BibiGPT → 关键视频字幕下载 → 深度分析

Layer 3（付费 · 自动化 · 等有预算再接入）
  └─ TikHub → 播放量+字幕+评论 → 全自动深度数据
```

## 6. 自部署 RSSHub（推荐）

公共实例 `rsshub.app` 有缓存和频率限制，长期使用建议自部署：

```bash
docker run -d --name rsshub -p 1200:1200 diygod/rsshub:latest
```

部署后使用 `http://你的服务器:1200/bilibili/user/video/{UID}` 即可，无缓存限制。

## 7. 三平台方案对比

| | YouTube | X(Twitter) | B站 |
|:----|:---:|:---:|:---:|
| 免费层 | 官方 API + RSS | — | **RSSHub** |
| 免费数据深度 | 元数据 + 字幕 + 评论 | — | **标题 + 描述 + 时间** |
| 付费层 | 不需要 | TwitterAPI.io $2/月 | **TikHub（按需接入）** |
| 付费数据深度 | — | 推文 + 互动 | **播放量 + 字幕 + 弹幕 + 评论** |
| 合规性 | ✅ 官方授权 | ⚠️ 判例支撑 | ✅ RSSHub（公开网页）/ TikHub（第三方扛风险） |
| 每日上限 | 48 条完整 | 300 条推文 | 无硬性限制 |
| 自部署 | 不需要 | 不需要 | **推荐自部署 RSSHub** |

> B站作为中文 AI 知识社区，虽然基础层数据深度不如 YouTube，但其 UP主生态（深度评测、教程、行业分析）对国内 AI 工具选型有独特价值。需要深度数据时，TikHub 可按需接入，与 X 的 TwitterAPI.io 逻辑一致。
