# 软件维护

## ⑧ 软件维护 —— 改正 + 适应 + 完善 + 预防

> **环归属**：环 B（先行就位）— Issue 模板、纠错流程等现在开始运作，不等编码完成。

本目录汇集 InfoCatcher 上线后的维护相关工件。

## 维护机制概览

**三层信息更新流水线**（应对可行性研究 R2 极高风险：信息更新跟不上行业速度）：

```
用户提交 ──▶ AI 初审（v1.0+）──▶ 人工审核 ──▶ 入库
   │            │                  │
 GitHub       预审过滤           维护者确认
 Issues       低质量提交         合并入库
```

| 层 | 职责 | 阶段 |
|------|------|:---:|
| 用户提交 | 通过 GitHub Issue 模板结构化提交纠错/新工具 | 现 MVP |
| AI 初审 | 自动预审：字段完整性、来源可信度、事实抽查 | v1.0+（可选） |
| 人工审核 | 维护者最终确认合并 | 现 MVP |

## GitHub Issue 模板（位于仓库根 `.github/ISSUE_TEMPLATE/`）

> ⚠️ `.github/ISSUE_TEMPLATE/` **必须放在仓库根目录** GitHub 才能识别为议题模板，因此物理路径在根目录，但逻辑归属"软件维护"阶段。

| 模板 | 用途 |
|------|------|
| `data-correction.yml` | 结构化纠错（tool_name/field/current_info/correct_info/source 必填） |
| `new-tool.yml` | 结构化新工具推荐 |

**部署前必做**：模板中的仓库链接含 `wozore` 占位符，上线前需替换为实际用户名。
