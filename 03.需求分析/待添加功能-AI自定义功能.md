## 1. 背景

传统开源项目自定义添加功能的路径：

```
阅读源码 → 理解架构 → 手写代码 → 提 PR → 等待合入
```

门槛高、周期长，普通用户难以参与。

AI Vibe Coding 时代的新路径：

```
克隆仓库 → 对 AI 说"帮我加个 XX 功能" → AI 理解代码结构 → AI 生成代码 → 本地生效
```

用户不再需要深入理解整个代码库，只需要项目本身**结构清晰、文档到位**，AI 就能准确地进行修改和扩展。

---

## 2. 核心思路

InfoCatcher 要做的是：**让代码库对 AI 友好**，使得用户通过 AI 编码工具就能自定义添加功能。

这不是一个"运行时功能"，而是一种**设计原则**贯穿整个开发过程：

| 原则 | 做法 | 对 AI 的好处 |
|------|------|-------------|
| **清晰的目录结构** | 功能模块分离，路径命名直观 | AI 快速定位需要改的文件 |
| **显式的数据流** | 数据 → 视图 → 交互分层明确 | AI 理解修改影响范围 |
| **CLAUDE.md / README** | 记录架构决策、编码约定、扩展点 | AI 遵循项目规范生成代码 |
| **一致的编码模式** | 组件/函数保持相同风格 | AI 生成的代码与现有代码一致 |
| **注释扩展点** | 标注 `// EXTENSION POINT` 便于 AI 识别 | AI 知道在哪里插入新功能 |

## 3. 在 InfoCatcher 中的实现

### 3.1 方案1 阶段（环 B — 立即开始）

当前 MVP 代码就可以应用此原则：

```
mvp/
├── index.html          # 入口（可扩展导航按钮）
├── css/
│   └── style.css       # 样式（CSS 变量体系，扩展新视图不影响现有）
├── js/
│   └── app.js          # 主逻辑（模块化函数，新增功能只需添加新函数 + 注册）
└── data/
    └── tools.json      # 数据（扩展新字段不影响现有字段）
```

**示例：用户想加一个"工具收藏夹"功能**

用户对 Claude Code 说：
> "帮我在 InfoCatcher 加一个收藏功能，用户可以收藏自己喜欢的工具，在顶部导航加一个'收藏夹'按钮"

由于代码结构清晰，AI 可以：
1. 在 `app.js` 添加收藏状态的 CRUD（localStorage）
2. 在 `index.html` 添加收藏夹视图区 + 导航按钮
3. 在 `style.css` 添加收藏相关样式
4. 在工具卡片上添加"收藏"按钮

用户不需要手写一行代码。

### 3.2 方案3 阶段（环 C — 进阶扩展）

配合 Serverless 后端，可进一步提供：

| 机制 | 说明 |
|------|------|
| **扩展点注册表** | 在代码中显式声明所有扩展点，AI 可以直接读取 |
| **自定义功能模板** | 提供 `add-feature.sh` 脚手架，AI 可调用 |
| **社区功能市场** | 用户分享自己通过 AI 定制的功能配置（非代码，是描述文本） |

## 5. 与插件系统的关系

| 维度 | 运行时插件系统（C05） | AI 自定义功能 |
|:----:|---------------------|-------------|
| 目标用户 | 普通用户（不碰代码） | 开发者/技术用户 |
| 扩展方式 | 安装预制插件 | AI 直接修改代码 |
| 灵活性 | 受 API 限制 | 无限（任何能改代码的事都能做） |
| 适合场景 | 标准化扩展（数据源、视图） | 个性化深度定制 |
| 启动时机 | 环 C Serverless 到位后 | **环 B 即可开始** |

两者互补：**插件系统覆盖"常用标准化扩展"，AI 自定义功能覆盖"长尾个性化需求"**。
